# Contributing

Welcome. Code, design, testing, documentation, and specific mobile use cases all help.

## Choose a small task

1. Read the README and roadmap.
2. Look through open issues. Comment on an existing task or open a contribution proposal with your role, intended outcome, and any help you need.
3. For large changes, agree on the scope in the issue before implementing them.
4. Submit a focused pull request linking the issue and explaining the change and how you checked it.

You do not need to write code to contribute. A clear bug report, a tested setup guide, or a design with error states can be a complete contribution.

## Code and build evidence

The application foundation has not been selected yet. For the Mercury evaluation, record the upstream commit, operating system, toolchain versions, exact commands, and results. Clearly separate successful checks from untested assumptions. Never claim an app works based only on its README.

Once application code is introduced, include setup and relevant verification instructions with it. Keep unrelated refactors out of a task's pull request.

## Credit and licensing

- Preserve source history where practical and retain all applicable third-party notices.
- Record the original repository, revision, files reused, and modifications in CREDITS.md when importing code.
- Submit only work you have the right to contribute. Original contributions use this repository's MIT license; third-party work keeps its applicable terms.
- Credit collaborators in the pull request. An offer of reusable code does not imply ongoing maintenance or endorsement.

## Working together

Be respectful, explain disagreements, and make room for beginners. Keep feedback about the work. Never publish credentials, private host URLs, personal conversations, or unredacted logs in issues, screenshots, or pull requests. Use synthetic examples for demos.

The repository owner reviews and merges initial contributions. Additional maintainer roles can be discussed as the project develops.
